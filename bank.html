💸 Passport Bank Setup

One verified payer, one verified recipient, fixed 1,000 L$ payments.

Much simpler payout rule

The first SL username in Settings is the payer. The second SL username is the recipient. Those same usernames label the tabs.

Adventure prizes accumulate in the recipient's balance. Nothing is payable until the balance reaches 1,000 L$. Every payment is exactly 1,000 L$. If the balance is 2,350 L$, two separate 1,000 L$ payments can be made and 350 L$ stays in the balance.

Real-money warning: once setup is complete, the in-world object has Second Life debit permission. The script is restricted to the verified recipient UUID, exactly 1,000 L$ per request, one pending payment at a time, and an owner approval dialog for every payment.

1. Put the real SL usernames in Settings

1
On Adventures, open Settings.
2
Enter the payer's actual Second Life username in the first field and the recipient's actual SL username in the second field. Do not use display names or nicknames.
3
Save. Those usernames now become the two tab labels and the identities Passport Bank verifies.

2. Create Passport Bank in Second Life

1
The payer avatar should rez any simple prim and own it personally. Do not deed it to a group.
2
Name it something like Passport Bank. Open Contents, create a new script, replace the default code with the script below, and save.
3
Touch the object. It gives the owner an 8-digit pairing code.
Loading script…

3. Pair and verify

Back on Adventures, enter the 8-digit code in the Passport Bank box and press Pair Bank.

The in-world object then checks that its owner really is the first username and resolves the second username to that avatar's UUID. Only after both identities match does it request debit permission from the payer.

Changing either username later intentionally breaks the identity match. Use Reset Pairing on the in-world object and pair again.

4. Test without completing adventures

Use 🧪 Give [recipient] 1,000 L$ test earnings on the Adventures page. This temporarily acts as though the recipient has earned the 1,000 L$ threshold, without changing any adventure or reward history.

Important: only the earnings are fake. If you press Pay 1,000 L$ and approve the in-world dialog, the resulting transfer is a real 1,000 L$ payment from payer to recipient. After a successful test transfer, the temporary test earnings return to zero.

5. Normal use

Real adventure rewards accumulate until at least 1,000 L$ is unpaid. Press Pay 1,000 L$, approve the matching Second Life dialog, and the app waits for Second Life's transaction result before deducting exactly 1,000 L$ from the reward balance.

If 1,000 L$ is not yet earned, there is simply no payout to make.

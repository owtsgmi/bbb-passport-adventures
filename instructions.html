Bellisseria Passport Adventures

How couples and groups play independently

📖 How to Play

This is a lightweight group game built around BBB Passport stamp collecting in Second Life. Pick a three-stop adventure, travel together, collect stamps, and finish the whole trio on every participating passport.

Every couple or group has its own private club. Sign in from Settings, create a club, and send the invite link to the people playing with you. One account can belong to several completely independent clubs.

1. Set up your club

1
Open the ☰ menu, choose Settings, and create an account using your Second Life username and a password.
2
Create a club for this couple or group. New clubs start with Adventure Treasure off.
3
Make an invite link and send it to the other players. They sign in and join the same club.
4
Choose the active club in Settings whenever you want to switch groups.

Each player uses their own Second Life username account. Passport Adventures does not collect player email addresses.

2. Pick an adventure

Use ✨ Pick Random Adventure, filter by area, or open any adventure in the list. Each adventure has exactly 3 passport stops.

Every active player in the club is included when a new adventure starts. That player list is saved with the adventure, so later roster changes do not rewrite an adventure already in progress.

The current adventure stays pinned at the top so you can jump back to it easily while you're moving around Second Life. It is locked by default so an accidental tap on Pick Random Adventure or another adventure cannot replace it.

To intentionally switch, uncheck Adventure locked on the Current Adventure bar. The app will still ask for confirmation before replacing it, and the newly selected adventure locks itself automatically.

The adventure stop list stays clean: each stop row shows the BBB location photo, place, status, and its own Firestorm copy button. The old extra Travel / Next stop / Copy destination block above the list has been removed.

A zoomable Second Life map appears at the bottom of the current adventure and marks all three stops. Use Fit to frame the adventure or World to zoom out across the broader Second Life grid. Every stop in the current adventure is selectable: click the stop row or its 🎯 Focus button to reset any previous pan/zoom and jump the map back to region-level detail for that stop.

3. Everyone finishes together

One person can get ahead, but the adventure is not complete until every active player included in that adventure has all three stamps. The player tabs show each passport separately, while each stop reports how many group members have it.

The NEXT marker points to the first stop the whole group has not finished. After a player uses Test & enable StaFi once, the server checks that private StaFi page automatically about every two minutes while the club has a current adventure; opening or returning to Adventures also triggers a quick refresh. Mark stamp remains available when manual tracking is needed.

4. Mystery L$ reward

When Adventure Treasure is enabled, each group-completed three-stop adventure reveals a random 20–100 L$ prize for the club's Paid to player. The Payer is always a different player.

The amount stays completely hidden while the adventure is in progress. It is generated once when every participating passport finishes all three stops, then saved inside that club so another club can never change it.

5. L$ adventure treasure

Each completed group adventure adds a hidden 20–100 L$ prize to that club's Adventure Treasure.

Adventure Treasure is optional and off by default. Any club member can turn it on from Settings. The person who turns it on becomes the locked Payer until they turn Treasure off again. When it is off, the next player who turns it on becomes payer.

When Adventure Treasure is on, it appears compactly beside the large passport counter. The current L$ total is visible at a glance; open it only for the milestone, lifetime total, waiting status, or recent prizes. At 1,000 L$, the beneficiary sees Get Your 1,000 L$ Bonus. This creates a request for that club's payer/admin; it never moves L$ automatically.

The locked Payer chooses who is Paid to and sends L$ manually in Second Life. When at least 1,000 L$ is ready, that payer can use Mark 1,000 L$ paid in Settings after the payment is actually sent.

6. Passport progress

The top stamp counter shows the whole passport total, not only the fixed adventure subset. When StaFi is connected, the app reads the live BBB summary from that player's private page, including collected, uncollected, and all currently available stamps.

For example, if StaFi reports 1 collected and 390 currently available, the header shows 1 / 390 stamps · 389 to go.

After saving a private StaFi link, use Test & enable StaFi once. Only confidently identified collected stamps from the current adventure are imported; ambiguous page content never marks a stamp.

Club privacy rule: adventures, players, stamp progress, rewards, and payout requests are scoped to the active club. Joining another club never merges the two games.

🏗 App Architecture

A plain-English map of how Passport Adventures works today. This section is intentionally kept as living documentation for users and for future development.
GitHub Pages UI→Passport login→Private clubs+BBB live catalog

Front end

The app is a static GitHub Pages site built from plain HTML, CSS, and JavaScript.

  • Adventures: the active club's game board with dynamic player tabs and a deliberately simple player-facing header.
  • Instructions: user guide plus this architecture reference.
  • BBB Stops: searchable live-aware stop catalog, nearby-stop tools, images, and Second Life map display.
  • Comments & Bugs: public suggestions and bug reports.

Game data

The core adventure set is a stable snapshot of 381 campaign stops grouped into 127 three-stop adventures. That dataset is intentionally kept stable so BBB catalog changes do not silently rearrange current adventures or reward history.

The whole-passport counter may include stamps outside that campaign snapshot.

Shared state & rewards

Supabase stores each club's current adventure, participant snapshot, per-player stamp progress, Treasure rewards, and payment history.

Adventure Treasure is controlled from Settings. The first active member who turns it on becomes the locked payer until that person turns it off. The payer sends L$ manually in Second Life and records each completed 1,000 L$ payment in Settings.

The player-facing Adventures page keeps bookkeeping out of the way and focuses on the current adventure, passport progress, and optional Treasure total.

Private settings

Each account uses a Second Life username and password. Passwords are stored only as one-way hashes, login sessions are revocable, and club membership plus owner/admin roles control access. A signed-in player's raw StaFi URL stays in that player's private settings and is never included in the club roster payload.

No email address is collected. There is no email-based password recovery, so players should keep their password somewhere safe.

BBB catalog mirror

The BBB Stops page checks the public BBB catalog whenever that page opens. A Supabase Edge Function fetches and parses the BBB source, returning current stop locations and available images.

Matching stops refresh their public location/image information. Those same original BBB location photos are reused beside stops on both the Adventures page and the BBB Passport Stops page, including selected/nearby stop views. The backend keeps a shared catalog cache so pages do not have to wait on the slower BBB site every time they open. Newly discovered stops can appear as BBB Live catalog entries without changing the 127 existing adventures.

Both the stop page and the current-adventure page use a shared Second Life grid-map component. It loads Linden Lab map tiles at multiple zoom levels, supports drag/zoom, and can move from local region detail to a broad world view. Mouse-wheel zoom is debounced to avoid request bursts, and unavailable tiles are retried once before falling back to a clean placeholder instead of a broken-image box.

StaFi passport progress

Each player's personal BBB StaFi page is saved privately and never returned in a club roster. After the player tests the link, a protected Supabase job checks it about every two minutes while that player has a current adventure. The page's summary also supplies the live collected/available passport totals. Adventures performs an additional refresh when opened or brought back to the foreground. Manual marking remains available if the external page is unavailable.

Feedback system

The Comments & Bugs page stores public feedback in Supabase. There is no user account list yet, so people choose any display name they want.

Anyone can submit feedback, but only the site owner has the separate Owner Passphrase used to edit, resolve, hide, reopen, or permanently delete entries. The Owner Passphrase is not stored in the public site source; only a one-way hash is stored server-side.

Users should never post passwords, Owner Passphrases, or private StaFi links there.

Multiuser clubs today

SL-username/password accounts, independent clubs, invite links, owner/admin/member roles, and club switching are live. A couple is simply a two-player club; larger groups can keep a bigger roster and choose the participants for each adventure.

Every new adventure snapshots all currently active club players. Per-player stamps, run completion, Treasure rewards, collection requests, and payment records remain inside that club.

Treasure uses a first-enabler lock: the first active member who turns it on becomes payer until that same person turns it off. Reward amounts are generated by the authenticated backend only after all snapshotted participants finish the adventure; browsers cannot submit or alter reward amounts.

The shared public BBB catalog stays global/read-only; private passport progress and club gameplay stay isolated per user and club.

Current boundaries

  • The app does not automate Linden-dollar transfers. Real payments are made manually in Second Life, and payment controls live in Settings rather than the player-facing Adventures screen.
  • The public BBB mirror and the private StaFi progress system are separate.
  • Feedback submission is public, but curation is owner-only through a separate private Owner Passphrase.
  • Nearby-stop ranking is best-effort until complete grid-wide coordinates are available.
  • StaFi sync runs server-side on a schedule while a current adventure is active, with extra foreground checks from Adventures. It fails closed: ambiguous page content is not treated as a collected stamp.
  • Owner-only moderation is code-based rather than account-based: anyone who possesses the private Owner Passphrase would have curator rights, so that code must remain private.
Living documentation: whenever the app changes in a meaningful way, the user instructions and this architecture section should be updated in the same development pass so the site remains its own reference manual.

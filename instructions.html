How couples and groups play independently

📖 How to Play

Pick a 3-stop BBB Passport adventure and play in the style that fits your club.

Three modes are live: 🧭 Solo, 💗 Babygirl, and 👥 Group. One account can belong to several independent clubs.

1. Set up your club

1
Create an account with your Second Life username and password. No email is collected and there is no password recovery.
2
Create a club and choose Solo, Babygirl, or Group.
3
Solo: 1 player, no L$. Babygirl: exactly 2 players, Payer + Babygirl, with Treasure. Group: 2+ players, no L$.
4
Use the selected club's invite button for Babygirl or Group, and switch clubs anytime from Settings.

2. Pick an adventure

Use ✨ Pick Random Adventure or open the collapsed Potential Adventures section and filter by area. Every adventure has exactly 3 stops.

Starting an adventure snapshots all currently active club players, so later roster changes do not alter that adventure.

Current Adventure stays at the top and opens automatically when active. It is locked by default; unlock it to switch, confirm the change, and the replacement locks again.

Each stop shows its BBB photo, place, status, and Firestorm copy button. The map shows all three stops; use Fit, World, or 🎯 Focus on a stop.

3. Finish the adventure

Solo: you reach 3/3. Group: the first participant to reach 3/3 finishes the adventure. Babygirl: both passports must reach 3/3, so the mode rewards teamwork. Player tabs still show each passport separately.

NEXT follows the viewed player in Solo/Group; in Babygirl it points to the first stop either partner still needs.

After Test & enable StaFi, the server checks that player's private StaFi page about every 2 minutes while the club is recently active. Checks stop after about 10 inactive minutes and resume when Adventures is opened or revisited. Mark stamp remains available manually.

4. Babygirl Treasure

Treasure exists only in Babygirl mode. The club has exactly two roles: Payer and Babygirl.

Each adventure reveals one saved random 20–100 L$ reward only after both passports have all 3 stamps. Rewards accumulate for the Babygirl toward 1,000 L$.

The Payer sends real L$ manually in Second Life, then uses Mark 1,000 L$ as paid. Solo and Group have no money system.

5. Passport progress

The header shows the whole live passport total, not just the fixed adventure set. With StaFi connected it uses that player's private BBB summary, for example 1 / 390 · 389 to go.

Only confidently matched stamps from the current adventure are imported automatically. Ambiguous StaFi content never marks a stamp.

6. BBB Stops

The BBB Stops page searches the live-aware catalog by text, area, and collected/needed status. Selecting a stop shows 6 nearby suggestions and maps all 7 locations together.

Nearby ranking prefers same-region coordinate distance, then the same broader area. It is best-effort until complete grid-wide coordinates are available.

Club privacy rule: club players, adventures, stamp progress, rewards, and payment history stay inside the active club. Joining another club never merges games.

🏗 App Architecture

A compact reference for how Passport Adventures works.
GitHub Pages UI→Passport login→Private clubs+BBB live catalog

Front end

Static GitHub Pages using HTML, CSS, and JavaScript.

  • Adventures: active-club game board and player tabs.
  • Settings: account, club mode, invites, StaFi, and Babygirl Treasure.
  • BBB Stops: searchable catalog, nearby stops, photos, and map.
  • Comments & Bugs: public feedback.

Game data

The adventure set is a stable 381-stop / 127-adventure snapshot. Live BBB changes can update the searchable catalog without silently rearranging adventures or reward history. The whole-passport total can be larger.

Club state & rewards

Supabase stores each club's mode, current adventure, participant snapshot, per-player stamps, and any Babygirl rewards/payments. The backend enforces each mode's player count and completion rule.

Accounts & privacy

Accounts use SL username + password. Passwords are one-way hashed, sessions are revocable, and owner/admin/member roles control club access.

Raw StaFi URLs stay private to their owners and never appear in club roster data. No email is collected.

BBB catalog & maps

A Supabase Edge Function parses and caches the public BBB catalog, including locations and available photos. New public stops may appear as BBB Live without changing the fixed adventure set.

The shared SL grid map uses Linden tiles with drag, zoom, Fit, and World. BBB Stops fits the selected stop plus 6 nearby markers; Current Adventure maps its 3 stops. Failed tiles are retried once, then shown as clean placeholders.

StaFi sync

Each player's private StaFi page can be verified once, then checked server-side about every 2 minutes only for recently active clubs with a current adventure. Adventures also refreshes on open/return. Manual marking remains available.

The parser supplies collected/available totals and imports only confident current-adventure matches; ambiguous content fails closed.

Multiuser clubs

Clubs use explicit modes: Solo = 1 player; Babygirl = exactly 2 players and both must finish; Group = 2+ players and first to 3/3 finishes. Starting an adventure snapshots the active roster. Only Babygirl has Treasure.

The public BBB catalog is global/read-only; private passport progress and gameplay are isolated by user and club.

Feedback

Comments & Bugs stores public feedback in Supabase. Anyone may submit; only the owner can curate it with a separate private Owner Passphrase whose plaintext is not stored in public source.

Never post passwords, Owner Passphrases, or private StaFi links.

Current boundaries

  • No automatic Linden-dollar transfers; Babygirl payments are manual.
  • Public BBB data and private StaFi progress are separate systems.
  • Nearby ranking is best-effort without complete grid coordinates.
  • StaFi fails closed on ambiguous page content.
  • Feedback moderation depends on keeping the Owner Passphrase private.
  • Shotgun race mode is planned but not implemented yet.
